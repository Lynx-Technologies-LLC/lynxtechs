# v1.2.5

_Released 2026-10-01_

## Highlights

This release fixes a set of problems found while bringing up Elmo Platinum drives that use
modular (slot-based) configuration. It also makes failures much easier to diagnose when a drive
does not reach Operational or does not enable.

## Bug fixes

- **Modular drives now get a correct ENI from `lxmaster eni gen`.** For devices whose ESI
  describes modules through slots (such as the Elmo Platinum), the generator no longer
  duplicates the process data of each module. Previously the generated process image could
  contain every PDO twice, so the drive never left "Switch On Disabled".
- **Module selection when generating ENIs.** You can now choose which module goes into each slot
  when generating an ENI. The slot configuration is written in the form the drive expects.
- **Startup configuration order.** The drive's module/slot configuration is now applied before
  its PDO configuration, and the PDO layout the drive reports is checked against the ENI before
  the network starts. A mismatch is reported clearly instead of showing up later as a stuck
  drive.
- **Inputs read correctly when the ENI leaves a gap between outputs and inputs.** On such ENIs
  the inputs were read from the wrong place in the process image, so they always read as zero and
  the bus reported a working-counter error.
- **ENIs from other tools load correctly.** ENIs exported by TwinCAT and similar tools
  (`ModuleHandle`, `CompleteAccess="true"`, `Fixed="true"`) are now accepted and interpreted
  correctly.
- **Slow drives have more time to reach Operational.** The wait for the Operational state is now
  based on elapsed time rather than a fixed number of cycles, so drives that take a moment to
  synchronize are no longer cut off early.
- **`lxmaster eni gen --help` works without root.**

## Improved diagnostics

- **Full EtherCAT AL status code table.** All standard codes now have names, including the
  distributed-clock sync errors (`0x002C`, `0x002D`) that previously showed as "Unrecognised
  code".
- **Clearer report when Operational is not reached.** The report shows which slaves did not reach
  Operational, the working-counter history, the AL status codes seen, and the drive's
  distributed-clock sync state.
- **Bus-fault reports no longer blame cabling** when every slave is still responding. Output and
  input working counters are reported separately, so you can tell a lost link from a slave that
  refuses its process data.
- **Report when a CiA402 drive does not enable.** If a drive does not reach Operation Enabled,
  the exit report includes its state history, statusword, error code, and the commands that were
  sent.
- **Clearer startup configuration errors.** When a startup configuration write fails, the error
  includes the drive's abort reason and the data that was sent. If process-data mapping fails,
  the error says why.
- **The ENI check warns about suspicious process-image layouts**, such as unexpected gaps or
  overlaps between outputs and inputs.
- **Mode of operation may be unmapped.** Applications can now tell whether the drive reports its
  current mode of operation in the process data, instead of reading a misleading value.

## Changes

- Removed messages that told users to rebuild with a CMake debug option. Those messages did not
  apply to installed packages.
- Updated the `eni gen` documentation for module selection and startup SDO options.

## Known issues

- After a run that fails to reach Operational, the drive may stay in SAFE-OP with a sync error
  (AL `0x002D`). The next start then logs one failed INIT attempt and recovers on retry. A fix is
  planned for the next release.
- ENI validation rejects some valid TwinCAT ENIs that use combined read/write (LRW) process-data
  datagrams, and its layout warning can be misled by TwinCAT's mailbox-status mapping. lxmaster
  does not run LRW-based ENIs either way. Generate the ENI for lxmaster with `lxmaster eni gen`.
