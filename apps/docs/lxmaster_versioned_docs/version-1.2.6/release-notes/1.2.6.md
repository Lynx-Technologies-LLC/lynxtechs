# v1.2.6

_Released 2026-10-02_

## Highlights

This release closes generic EtherCAT master gaps that showed up after v1.2.5: a drive left in
SAFE-OP with a sync error no longer fails the next start's first INIT attempt, CoE emergency
messages are kept and reported, third-party TwinCAT ENIs validate correctly, and multi-slave
distributed-clock buses get per-hop propagation-delay compensation.

## Bug fixes

- **Downward state requests now acknowledge latched AL errors.** INIT, PRE-OP and BOOT are
  requested with the error-acknowledge bit set, matching TwinCAT. A slave that sat in SAFE-OP
  with "No SYNC error" (AL 0x002D) after a failed run now steps down on the first try instead of
  needing a retry.
- **SYNC0 is turned off after PRE-OP, not before.** Disabling the sync unit while a DC-strict
  slave is still in SAFE-OP was what latched that 0x002D. Shutdown now takes the drives from
  SAFE-OP to PRE-OP while process data and SYNC0 are still running, then disables SYNC0, then
  requests INIT. Generated ENIs use the same acknowledge bit on their INIT and PRE-OP InitCmds.- **TwinCAT-style ENIs pass validation.** Combined read/write (LRW) datagrams now use the
  standard working-counter rule (write +2, read +1). Mailbox-status FMMUs are ignored when
  checking the process-image layout, so a known-good TwinCAT ENI is no longer rejected.

## Improved diagnostics

- **CoE emergency (EMCY) messages are captured and reported.** Emergencies that arrive during
  an SDO exchange, and those still sitting in a slave's mailbox at shutdown, are kept per slave
  and   printed on the device status report and on a CiA402 enable-failure report. They are also
  logged as they are received. Both the LXEC and SOEM backends collect them.

## Changes

- **Distributed-clock propagation delay is measured and programmed.** On a bus with several DC
  slaves, each slave's delay is computed from the port receive times of one latch (the same
  method SOEM uses) and written to the ESC before SYNC0 is armed. A short static
  drift-compensation burst runs first so the clocks have settled before Operational is requested.

## Known issues

- A slave that drops off the bus in Operational still stops the network. Re-admitting a
  reconnected slave without restarting the whole bus is not implemented.
